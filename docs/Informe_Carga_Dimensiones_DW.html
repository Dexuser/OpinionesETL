1. Descripción del proceso

Las dimensiones del modelo en estrella se cargan desde el staging (esquema stg) mediante el procedimiento stg.sp_cargar_dw, que el Worker Service invoca dentro de una única transacción después de la extracción de las tres fuentes. La carga es código SQL ejecutado desde C# (Npgsql): no requiere herramientas gráficas.

1.1 Flujo

  1. Extracción en paralelo (Task.WhenAll): CSV de encuestas, base operacional (reseñas web, clientes y productos) y API REST de comentarios sociales.
  2. Staging: cada extractor reemplaza sus filas en stg.opinion, stg.cliente, stg.producto y stg.rechazo con COPY binario, en una transacción por fuente.
  3. Carga: CALL stg.sp_cargar_dw(...), que carga las dimensiones en el orden indicado y después los hechos.

1.2 Orden de carga de las dimensiones

Idempotencia. Todas las cargas usan claves naturales con ON CONFLICT, así que ejecutar el proceso varias veces no duplica dimensiones ni hechos. La segunda ejecución de la prueba reporta 0 días nuevos y 0 fuentes nuevas.

4. Conclusión

Las siete tablas de dimensiones y la tabla de hechos del modelo se cargan desde staging con el procedimiento stg.sp_cargar_dw, invocado por el Worker. La carga reproduce los conteos esperados (706 hechos, 494 rechazos, 395 días), es idempotente, y no deja hechos huérfanos. El código fuente completo, incluidos los scripts SQL y el Worker, está en el repositorio: https://github.com/Dexuser/OpinionesETL.
